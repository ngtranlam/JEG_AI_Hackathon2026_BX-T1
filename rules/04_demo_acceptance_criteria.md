# Rule 04 — Demo Acceptance Criteria

The web app demo is accepted only if it clearly proves the end-to-end workflow.

## Required demo flow

A judge should be able to see:

```text
1. Fill in brief
2. Upload logo/product image
3. Click Generate 2 Video Variants
4. See workflow progress
5. See Variant A and Variant B side by side
6. Play both videos
7. View hook/script/storyboard
8. See publishable score
9. Download 9:16 and 1:1 outputs
```

## UI quality requirement

The UI should be:

```text
Minimal
Professional
Clean
Readable
Demo-ready
```

It does not need:

```text
Fancy animation
Complex dashboard
Authentication
Team management
```

## Required input fields

The UI must include:

```text
Brand name
Product/service name
Product description
Target audience
Platform
Target duration
Brand tone
Main message
Campaign goal
Compliance constraints
CTA
Logo upload
Product image upload
Optional moodboard upload
```

## Required output cards

The output section must have 2 side-by-side cards:

```text
Variant A
Variant B
```

Each card must show:

```text
Video preview
Variant name
Creative direction
A/B hypothesis
Selected hook
Duration
Publishable score
Download buttons
```

## Required comparison table

Below the two video cards, show:

```text
Creative angle
Hook
Target emotion
CTA
Publishable score
```

This proves the variants are not duplicates.

## Required progress display

The app must show workflow node status:

```text
pending
running
completed
failed
```

## Required export buttons

At minimum:

```text
Download Variant A 9:16
Download Variant A 1:1
Download Variant B 9:16
Download Variant B 1:1
Download workflow report
```

Nice to have:

```text
Download all as ZIP
Copy caption
View script/storyboard
```

## Final demo success statement

The demo should support this pitch:

> This is not a generic video generator. It is a TRAE-orchestrated content factory that transforms a brand brief into two publish-ready short-form video variants.
